# Independent publication and data-refresh workflows

A website change previously waited for the full FAOSTAT/World Bank refresh. If the data job was slow or failed, the site remained on its old code. The snapshot publication workflow now runs on main pushes and manual requests, using only the data branch's last verified release. It verifies every file size and SHA-256 before testing/building the site. The refresh workflow continues on its schedule, manual requests and pipeline changes; only successful data validation can publish fresh data. Both new Pages publication jobs serialize deployments, and the refresh deploy checks out latest main so an old refresh cannot overwrite newer site code. The prior in-flight workflow may still complete once under its old definition. UI coverage labels show the actual product forms present in the snapshot, not registry targets. No source data is fabricated.
